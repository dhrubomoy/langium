## Codebase Patterns
- This is an npm workspaces monorepo. Tree-sitter binary is hoisted to root `node_modules/.bin/tree-sitter` even when declared as devDep of `packages/langium-cli`. Verify with `cd packages/langium-cli && npx tree-sitter --version`.
- Pre-existing test failures: 119 langium-cli tests fail with `Object.groupBy is not a function` because the sandbox runs Node 20.19.4 but `Object.groupBy` requires Node 21+. This is NOT introduced by tree-sitter changes; verify any new test failures are not on this list before claiming a regression.
- TypeScript typecheck for the monorepo workspace: `npx tsc -p packages/langium-cli` (no output means success).
- Run langium-cli tests in isolation: `npx vitest run packages/langium-cli`.
- Tree-sitter artifacts live in `packages/langium-cli/src/grammar-parser/lang/` (grammar.js, langium-grammar.wasm, generated C parser sources, the commonjs `package.json` override, tree-sitter.json). The parent `src/grammar-parser/` is ESM and contains the TypeScript sources (`grammar-parser.ts`, `grammar-queries.ts`). Do NOT put any `.ts` files inside `lang/` — they would inherit `type: "commonjs"` and break under `verbatimModuleSyntax`.
- The `lang/` directory needs its own minimal `package.json` with `"type": "commonjs"` because langium-cli's package.json declares `"type": "module"` and tree-sitter's `grammar.js` uses CommonJS `module.exports`.
- Tree-sitter's regex engine (`regex-syntax` crate) does NOT support look-around (`(?=...)`, `(?!...)`, etc). When porting a Langium regex into grammar.js, rewrite lookaheads as character-class enumeration inside `token(seq(...))`.
- `tree-sitter generate` writes its output to the CWD's `src/`, NOT relative to the grammar.js argument. Always `cd src/grammar-parser/lang && tree-sitter generate` (matches the build:grammar-wasm npm script). Running it from `packages/langium-cli` with the path arg dumps output in the wrong place.
- `tree-sitter generate` is hardcoded to find a file literally named `grammar.js` in CWD; passing a path like `grammar.cjs` or `./other-name.js` does NOT work even if Node would otherwise resolve it.
- `tree-sitter build --wasm` requires either Docker with platform-matching emsdk image or a local `emcc`. The bundled docker fallback uses `emscripten/emsdk:3.1.64` which is amd64-only; on arm64 hosts install emscripten locally (`apt-get install emscripten` on Ubuntu, gives 3.1.69 which works fine).
- web-tree-sitter v0.26+ uses NAMED exports (`import { Parser, Language } from 'web-tree-sitter'`) and `Language.load(...)` is a static method on `Language`, not on `Parser.Language`. The plan's smoke-test snippet is for the v0.20 API.
- web-tree-sitter v0.26 has no `SyntaxNode` export — the class is `Node`. Re-export it under a `SyntaxNode` alias from `grammar-parser.ts` if downstream code expects that name.
